# Wide-character foundation (Phase 7)

This increment supplies Unicode source, contextual wide literals, scalar text
attributes, and Ada.Characters.Conversions. The overall wide-library roadmap
item remains open: Wide_Text_IO/Wide_Wide_Text_IO, their generic children and
instances, and the wide string/map families still need implementation. This is
not a claim of complete predefined-library conformance.

## Source and identifiers

Source files use strict UTF-8, with an optional initial UTF-8 BOM. Overlong and
truncated sequences, surrogate encodings, and values beyond U+10FFFF diagnose.
Positions FFFE/FFFF in every plane are forbidden throughout a source file,
including comments. Other character values remain constructible with Val;
Wide_Wide_Character retains its Ada 2005 range 0 .. 2**31-1.

The character properties and default uppercase mappings are pinned to Unicode
4.0.0, corresponding to ISO/IEC 10646:2003. They implement Ada 2005 RM
[2.1](https://www.adaic.org/resources/add_content/standards/05rm/html/RM-2-1.html)
and [2.3](https://www.adaic.org/resources/add_content/standards/05rm/html/RM-2-3.html),
rather than the host locale or a moving operating-system Unicode database.
Identifier starts, combining marks, decimal digits, connector punctuation and
format characters follow their Unicode categories. Format characters are
ignored when comparing identifiers and checking adjacent/trailing connectors.
Casing uses default Unicode uppercase mappings, including expansions such as
sharp-s to SS. A transformed identifier cannot become a reserved word.

Non-NFKC source is accepted with code-point semantics: no compatibility or
canonical normalization is performed. Consequently precomposed and decomposed
spellings remain distinct unless the specified uppercase/format transformations
make them equal. This defines the implementation-dependent semantics allowed
by RM 2.1(4.1). LF, NEL, LINE SEPARATOR and PARAGRAPH SEPARATOR advance source
line numbers; CRLF is accepted. Diagnostic columns count decoded characters.
Unicode separator spaces delimit tokens. Literal contents must be graphic
characters under the Ada 2005 definition; control values use Val or names.

ASCII source-unit stems retain their existing lowercase naming rule. Non-ASCII
characters in canonical unit stems use the same uppercase/format transformations
as name lookup. Explicit sources and bundles do not require filename guessing.
Linker symbols, local QBE names and elaboration identities escape non-ASCII
bytes with a reserved dotted prefix; distinct Unicode names cannot collapse to
the same underscore spelling. Expanded tagged and exception names retain the
Unicode name instead of the escaped linker spelling.

`common/UnicodeData.h` is generated by `scripts/generate_unicode.py` from the
pinned UnicodeData-4.0.0.txt and SpecialCasing-4.0.0.txt files. Input SHA-256s are
in the generated header; the inputs are available from the official
[Unicode 4.0 update directory](https://www.unicode.org/Public/4.0-Update/).
Builds and tests need no network. Redistribution terms are in
[UNICODE-LICENSE.txt](../common/UNICODE-LICENSE.txt).

## Literals, overloads and conversions

Character and string AST nodes retain code points. Character is Latin-1 with
one-byte elements, Wide_Character uses two-byte elements, and
Wide_Wide_Character uses four-byte elements. A supplementary character occupies
one Wide_Wide_String element, not a UTF-16 surrogate pair. String bounds count
characters, not UTF-8 bytes. Latin-1 characters in narrow literals retain their
single Character value, even though source spelling uses multiple UTF-8 bytes.

Resolution considers the standard character/string types, accepts the expected
wide type, and rejects genuinely ambiguous calls. Character subtype bounds do
not select overloads or prematurely reject a value of the base type; the normal
context checks still apply. Previously implicit narrow choices in context-free
literal comparisons need qualification, for example `String'("abc") < "abd"`.
Unicode character-literal enumerations, parameters, local variables, loop
variables and separate unit identities have execution coverage.

Ada.Characters.Conversions implements the complete Ada 2005
[A.3.4](https://www.adaic.org/resources/add_content/standards/05rm/html/RM-A-3-4.html)
set: membership predicates, all widening conversions, and narrowing conversions
with substitution. Array results have lower bound 1, including null arrays;
non-unit argument bounds are respected. These are positional character
conversions, not UTF-8 encoders/decoders. Ada.Characters.Handling exposes the six
[J.14](https://www.adaic.org/resources/add_content/standards/05rm/html/RM-J-14.html)
compatibility views. Both packages remain Pure and use ordinary Ada bodies.

## Text attributes and names

Image/Value/Width, Wide_Image/Wide_Value/Wide_Width and the Wide_Wide variants
use the appropriate string element width for the supported scalar types.
Numeric attributes reuse the existing checked parsers and formatters through
owned array results. Non-ASCII enumeration names use UTF-8 in narrow text and
native character elements in wide text; case comparison uses the same Unicode
uppercase mappings as the compiler. Control-character images use names such as
NUL and HT. Quoted control characters are not graphic literals and Value rejects
them; the numeric I/O grammar regression now checks the standard named form.

The implementation-defined spelling for a character that cannot appear directly
in the chosen image is `Hex_` followed by eight hexadecimal digits. Value accepts
that spelling where the corresponding image uses it. This covers nongraphic
wide values and values beyond the output character type. Width uses the same
policy without iterating the entire Wide_Wide_Character range. Supplementary
characters in a UTF-8 name widened to Wide_String use the twelve-cell escape
`["0001F600"]`; Wide_Wide_String keeps the actual code point. Wide exception
names decode the UTF-8 identifier rather than widening its individual bytes.

Attribute subprogram profiles beyond the existing Image/Value/Succ/Pred/Min/Max
adapter set, the remaining wide predefined libraries, and the broader Phase 8
privacy/freezing/overload audit remain separate obligations.

## Validation

`widefoundation` runs whole-program and per-unit execution and deterministic IR
checks. `unicodeunitbundle` exercises supplementary identifiers and distinct
Unicode library units through QBE. `semantics.unicode_source` covers pinned
Unicode-version behavior, BOMs, normalization policy, malformed UTF-8, forbidden
code points, contextual range errors and connector/reserved-word rules.
`wideambiguityerrors` pins ambiguous wide overload diagnostics.

The C runtime test round-trips every Wide_Character value and representative
31-bit Wide_Wide_Character values, checks buffer/parse failures and array-result
ownership, and repeats the work in four threads. ASan/UBSan and TSan cover the
instrumented compiler/C runtime; generated QBE memory accesses are not sanitizer
instrumented. Unchanged ACATS CXA3004 exercises the compatibility conversion API;
its provenance is recorded in tests/acats/README.md. The backfill cohort is unchanged.
